"OPEN") is present in this repo's current reusable-prioritizer.yml, so

pinned reference to this reusable workflow had not picked up the fix
yet. Net effect: a run that looks identical in the logs to a real,
useful pick did nothing but write noise to a dead issue, occupied the
run's WIP slot, and left the genuinely open ticket the comment refers
to untouched. Separately, adding the claude-work label to #8 should
have fired reusable-worker.yml's "issues" trigger; no such run appears
